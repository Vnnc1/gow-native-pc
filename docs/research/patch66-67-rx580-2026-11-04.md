## GS-07 / GS-08 / GS-09: new bounded candidates

- Patch 72 caches min/mag/wrap state on uploaded textures, resets on uploads and
  excludes render-target/depth/reinterpretation/replacement paths.
- Patch 73 specializes the existing shader only when DATE, software blending,
  depth aliases and reinterpretation are absent. It keeps program-specific uniform
  locations and falls back to the full shader if optional compilation fails.
- Patch 74 conservatively bounds vertex alpha only when texture alpha cannot
  affect it; it does not implement texture/CLUT alpha range analysis.
- Patch 75 supplies opt-in end-of-test path counters, not GPU timing. With periodic
  hardware statistics enabled, counters cover only the interval since the last flush.

All three remain OFF by default. Flags are `GOW_GS_SAMPLER_CACHE`,
`GOW_GS_FAST_SHADER`, `GOW_GS_ALPHA_BOUNDS`; setting each to 1 enables its candidate.
There is no normal-install performance improvement claim from these experimental flags.

Full `fetch,build,verify` passed: 17 CTest groups, VU1 backend equivalence and
bounded task replay. Sampler tests emitted 267 rather than 1200 driver setters
over the synthetic transitions. Alpha interval tests checked 67,371,008 cases.
Real OpenGL differential checks passed 384 frames for each of seven variants
(reference, sampler, shader, bounds, combined, forced shader fallback, reference
repeat), with identical color digests and explicit path coverage.

Initial uniform-color textures gave only five distinct hashes and were inadequate
for filtering validation. The accepted `pixels-pattern/` fixture uses nonuniform
CT32/T8/T4 2x2 textures, changing filters/wraps without reupload, DATE, software
blend and depth-alias fallbacks, with at least 16 distinct output hashes. These
synthetic color comparisons do not prove all game rendering or depth parity.
Early build failures (malformed diagnostic strings and an invalid test GL accessor)
were corrected; their logs remain beside the passing logs.

The six-run combined resource experiment (`efficiency/`) passed scene/exit/audio
checks, but showed 59.994→59.832 FPS, CPU 323.733→322.047% of one core,
GPU busiest-engine 45.230→43.899%, and median p95 17.327→17.333 ms.
One candidate run was 59.504 FPS. These short, variable samples do NOT establish
a reliable CPU/GPU improvement. Counters prove paths executed and redundant
sampler calls were avoided, not that total frame cost fell.
These candidate resource runs enabled bounded hardware-stat counters in both
variants (without per-call timers); they are diagnostic comparisons, not a
measurement of entirely uninstrumented public defaults.

An additional isolated sampler series (`sampler-resource/`) overlapped Python
pipeline regression checks during its early runs. Regardless of its functional
checks, this is contaminated resource/performance evidence and cannot justify
promotion. A future retest must cite this measurement flaw and run without
concurrent checks; the raw samples are retained.

The pipeline regression suite passed 17 tests; Linux orchestration passed seven
tests with one skip. These are correctness checks, not Linux GPU validation.

A separate visible arrival capture pair (`visual-arrival/`, reference versus all
three candidates) completed with all harness checks passing. Inspected captures
show the same ship, character, rocks and effects without an obvious rendering
regression. This is a short visual smoke, not sustained combat or a pixel-identical
game replay. Audio was enabled and counters checked; no subjective listening claim.
The isolated sampler series completed its functional gates, but remains excluded
from performance conclusions because of the concurrent regression checks above.

The harness now samples process CPU alongside PDH at two-second intervals,
checks process creation identity, and preserves unavailable metrics. CPU percent
can exceed 100 on multiple cores; GPU busy time is not GPU execution duration,
power, temperature or input latency. A stale session exit can only be recovered
with exactly one successful child-exit event AND helper exit zero; conflicting
or missing evidence is rejected. Unit checks cover these rules.

## Decision and remaining gates

Retain candidates as experimental reference-comparable implementations only.
No default promotion, new installer, universal 60-FPS or notebook gain is claimed.
Need sustained aligned gameplay, visible image/sound review, first-visit stalls,
and same-hardware tests on weaker Intel, AMD and NVIDIA systems. Do not repeat
completed synthetic checks as performance evidence; next work must address these
missing acceptance criteria or isolate a materially different candidate.

Future backend work is separate: [graphics API roadmap](graphics-api-roadmap.md).
