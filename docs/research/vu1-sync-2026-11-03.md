# VU1 and synchronization experiments (2026-11-03)

Target: improve normal installation/play without additional player settings. Local
hardware: Xeon E5-2666 v3, RX 580 2048SP, 16 GiB. These results do not establish
performance on the i3-10110U or weaker computers.

## Stage queue cache-line separation: rejected

Candidate: give the producer's `head` and consumer's `tail` separate 64-byte
alignment in `gs_stage.cpp`. Atomic ordering, wakeups, spin duration, capacity and
packet submission order were unchanged. Baseline includes texture patch 60
(`f269bfc2fe3762b9446e4124176c236b9a1833547d4e79fd6df2232d1e52be0c`).

Three alternating visible-gameplay pairs, 100 seconds each, excluding complete
windows that cross the first 40 seconds; 1x, audio enabled, precise VU default,
GS early FINISH on, large VIF barrier off, stage spin 50 us. Each run used a
private card. No compilation or intrusive profiling ran during the comparison.

| Pair | Baseline guest FPS | Candidate guest FPS |
| --- | ---: | ---: |
| 1 | 59.2364 | 59.3820 |
| 2 | 59.6164 | 59.4182 |
| 3 | 59.4209 | 59.7427 |
| Mean | 59.4245 | 59.5143 |

The +0.15% mean is inconclusive: one pair regressed and minimum-window FPS/p95
did not consistently improve. Reverted; no production patch. All six gameplay,
graceful exit, frame-accounting and effective-configuration checks passed.
Evidence: ignored `data/experiments/sync61/ab-valid/summary.json`. The earlier
`ab` directory is an invalid attempt: the undeployed helper lacked its DLL
environment and never started collection; it contributes no measurements.

The scripted route uses real-time inputs and is not guaranteed to remain
scene-identical between runs. It does not reproduce the notebook's 28-minute
scene, and its proximity to the 60 FPS cap limits sensitivity.

## Compact VU1 timing history: rejected

Candidate: store the timing history separately from its flag-tail payloads,
retaining the same ring index, capacity and lifetime. Both native entry points
use the separate tail array. No instruction arithmetic, emulated cycle timing,
JIT fallback or player setting changes.

The 128-record local MSCAL corpus passed hybrid, JIT, helper, SSE and exact
replay against each backend's captured baseline. Native/exact captured results
differ for all 128 records; this existing distinction is not a new parity claim.
Evidence: ignored `data/experiments/vu61/replay/summary.json`.

Five alternating measured replay pairs (one preceding warm-up pair, single
logical CPU affinity for repeatability) reduced the sum of per-record warm
medians from 2091.36 to 2083.58 us, -0.37%; all five pairs favored the candidate.
This is isolated JIT execution, not gameplay or weaker-hardware simulation.

The full `build.cmd -Stages verify` passed, including 11 native suites, procedural
VU1 backend equivalence, self-loop budget/depth exits and task capture/replay.
Actual game runs used the same settings/method as the queue experiment:

| Pair | Baseline guest FPS | Candidate guest FPS |
| --- | ---: | ---: |
| 1 | 59.7273 | 59.0345 |
| 2 | 59.3455 | 59.7818 |
| 3 | 59.1636 | 59.4355 |
| Mean | 59.4121 | 59.4173 |

Gameplay was effectively tied (+0.009%); no consistent p95 benefit. All six runs
passed their gameplay/exit/accounting checks. Reverted both header and entry
sites. Candidate runner SHA-256:
`74bcd47af9804b4d8243885ffd0aa76778d3da4d02946ea1cf628ef5fb1a4059`.
Evidence: `data/experiments/vu61/{pinned/comparison.json,ab/summary.json,verify.log}`.

## Grouped stage reclamation: rejected

Candidate: publish consumed ring space after at least 4 KiB or at the current
batch end, rather than after every packet. Submission remains per packet;
capacity, sequentially consistent ordering and final waiter notification remain
unchanged. This differs from the previously rejected batching of producer pushes,
which delayed packets reaching the GS frontend. Test it with baseline VU1 layout,
independently of the two rejected candidates above.

The production DMA/worker test passed: barrier configuration, early FINISH,
self-wait guards, 30,000 ordered packets through multiple ring wraps (including
heap-backed packets), idle waits and backend capacity/wakeup checks.

Three alternating gameplay pairs with the same method as above:

| Pair | Baseline guest FPS | Candidate guest FPS |
| --- | ---: | ---: |
| 1 | 58.9682 | 55.6718 |
| 2 | 59.5455 | 59.4727 |
| 3 | 59.5091 | 57.9694 |
| Mean | 59.3409 | 57.7046 |

The candidate lost all three pairs (-2.76% mean); lowest measured windows were
54.06 FPS for the baseline and 43.6 FPS for the candidate. Median window-p95
ranges were 17.085–17.125 ms versus 17.093–22.393 ms. All six functional run
checks passed. Candidate SHA-256:
`7e89ebfffa55d4d59d53c98e956a065847219b99a1eb437d6952163d0dcb94e1`.
Evidence: `data/experiments/sync62/{ab/summary.json,dma-tests.log}`.

Rejected. Fewer atomic publications did not improve this gameplay workload;
the measurements do not isolate scheduling effects from binary layout or route
variation. Preserve per-packet reclamation as well as per-packet submission.
