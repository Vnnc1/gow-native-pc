## Change and distinction from rejected experiments

The old chain body includes per-block checks for opcode statistics, sampled
cost accounting and native self-loop counters. The candidate instantiates that
same body for ordinary and detailed execution. One entry selection chooses the
detailed body when GOW_VU1_COST, GOW_VU1_OPSTAT or native diagnostics require it.
The ordinary body constant-folds the diagnostic paths away. Native diagnostics
remain per-interpreter; cost/opcode options retain startup configuration.

This does not remove emulated bookkeeping. Every block still updates history,
scalar pipelines, lane masks, cycle/stop/depth budgets and the guest PC in the
original order. Both AOT and JIT callers retain the exported chain interface;
no NativeState layout, generated code, ISA requirement, control input, guest
logic rate or synchronization ownership change is introduced. The existing
chain-warm option remains effective. Compiler-specific inline hints are guarded.

VU-01 changed calling convention; VU-02 changed a branch hint; VU-03 changed the
history layout; VU-04 outlined timing/scalar paths; VU-05 widened a self-loop
shortcut; VU-06 inlined block edges; VU-08 prefetches successor slots. None is
being repeated. OPEN-01 concerns guest timing elimination, not host diagnostic
branch specialization. The hypothesis was recorded before testing.

## Heavy-scene methodology

New `ship_altar_frames` contract: load the first slot from an explicit private
card copy into Athn01D, leave Kratos stationary and measure frames 600..2400.
The harness requires the same 30 trajectory checkpoints, gameplay state, no
movie and the correct zone; five-unit tolerance must not be widened to accept
another location. This is a heavy stationary ship/altar/water scene, not combat.
NPC/animation state is not a bit-identical replay.

Xeon E5-2666 v3 / RX 580 2048SP, 16 GiB, driver 31.0.21924.61. Visible 1280x720,
2x internal resolution, AF16, FXAA, exact VU, native IOP/AOT, audio, host cap 60,
VSync off, renderer grouping/ring/texture reuse on. Both variants use frames-only
metrics; no detailed VU/GS timing, task recording, profiler, screenshot or build
during the FPS series. Three alternating pairs: reference/candidate,
candidate/reference, reference/candidate. Each measured interval spans exactly
1800 guest frames, roughly 30 seconds, after initial loading/warmup.

The harness now accepts --card, --scale and --fxaa. Cards are copied separately
for every run, their source/copy hashes are checked, and existing/alias targets
are rejected. A scene requiring a save refuses to start without --card. Existing
blank-card defaults and the dedicated 1x/2x scale comparison remain unchanged.

Reproduction uses `tools/test/gs-run-ab.py --compare vu1 --scene ship_altar_frames
--grouping 1 --scale 2 --fxaa --pairs 3 --seconds 120 --warmup 30
--env GOW_GS_HW_RING=1 --env GOW_GS_TEXREUSE=1 --env GOW_ANISO=16`, plus explicit
--runner, --reference-runner, --elf, --collector, --card and a fresh --output.
The first card slot must contain the documented altar; other saves fail the
scene gate. No archive of the player's save is committed.
